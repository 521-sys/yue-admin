# 管理后台生产上线设计

日期：2026-10-16

## 目标与成功标准

在不新建服务器、不购买或配置新域名的前提下，将已完成本地验证的管理后台第一版发布到现有生产环境。管理入口为 `https://gnep.online/admin/`，后端继续通过同源 `/api/` 提供接口，现有用户网站继续使用 `https://gnep.online/`。

上线成功需同时满足：现有网站可正常访问；管理员可以登录后台；场景、台词、音频、用户进度和审计功能可用；已发布官方场景能被网页端读取；生产数据库由 Hibernate `validate` 校验通过；已有音频、用户数据、配音识别配置和用量文件不丢失。

## 范围与约束

本次复用现有服务器、域名、TLS 证书、MySQL、Nginx 和 `yue-backend` 服务，不增加 IP 白名单。后台使用现有管理员账号密码认证和 JWT；不得把密码哈希、数据库密码、JWT 密钥或腾讯云密钥写入仓库、构建产物或日志。

发布范围包括数据库迁移及种子数据、Java 后端、管理端静态站点、网页端公共场景接口适配。小程序代码可同步到远端，但微信正式版本发布及审核不作为本次服务器上线的阻塞项。网页仓库中与本任务无关的未提交语音改动和 `dist.tgz` 必须保留，不得覆盖或清理。

## 部署架构

Nginx 继续处理 `gnep.online`：根路径 `/` 服务用户网页，`/admin/` 服务管理端静态文件并提供 SPA 回退，`/api/` 反向代理 Java 后端。管理端以 `/admin/` 为 Vite 基础路径构建，接口基础地址使用同源 `https://gnep.online/api`。公共上传音频 `/audio/uploads/{opaque}` 必须转发到后端，不能被现有静态 `/audio/` 规则截获。

后端继续由现有服务管理器运行。生产环境显式设置 `SPRING_JPA_HIBERNATE_DDL_AUTO=validate`、`ADMIN_AUDIO_DIR`、`ADMIN_USERNAME` 和 `ADMIN_PASSWORD_HASH`，并保留已有数据库、JWT、微信及腾讯识别配置。管理音频目录使用持久化路径，和数据库作为同一恢复单元备份。

## 发布顺序与数据流

发布采用现有服务器上的分阶段切换，不创建新基础设施：

1. 核对四个独立仓库的提交、工作区和远端状态，重新执行发布所需测试与构建。
2. 暂停后台内容写入，备份 MySQL、后端 JAR、Nginx 配置、用户网页、管理端目录和管理音频目录。
3. 先在生产数据库的恢复副本或等价隔离库演练迁移，再对生产数据库依次执行 `admin-v1-migration.sql` 和 `admin-v1-seed.sql`。
4. 发布新后端并以 `validate` 启动，检查服务、数据库校验、既有接口和新管理/公共场景接口。
5. 发布 `/admin/` 静态产物并加载经 `nginx -t` 验证的路由配置。
6. 发布新版用户网页；小程序保持旧版本可用，后续单独提交微信审核。
7. 完成生产冒烟测试并记录实际提交号、构建摘要、备份位置和验证结果。

管理人员在后台保存并发布场景后，数据写入现有 MySQL；网页与小程序通过 `/api/public/scenes` 读取已发布内容。上传音频由 `/api/admin/audio` 写入持久目录并在数据库登记，公共播放通过后端控制的上传音频地址读取。

## 安全与错误处理

管理端对公网可达，但所有 `/api/admin/**` 业务接口必须要求管理员 JWT。密码哈希为空时禁止登录；上线前只检查配置是否存在和权限是否正确，不输出敏感值。Nginx 对管理音频上传请求允许 21 MiB，请求到达后端后仍执行 20 MiB 文件限制；其他 multipart 路由保持原限制。

数据库迁移、后端启动、Nginx 校验或核心冒烟测试任一失败时停止后续发布。迁移和种子脚本必须可重复执行，并保留运营已修改或已下架的数据。上线窗口内禁止同时从后台修改内容，避免备份点和文件索引不一致。

## 验证与回滚

发布前重新验证后端测试及打包、管理端测试及 `/admin/` 生产构建、网页测试及构建、小程序测试和类型检查、迁移/种子重复执行。生产冒烟测试覆盖首页、后台静态资源、管理员登录、概览、场景读取与编辑、发布后网页可见性、音频上传/读取、未授权接口返回 401，以及既有配音识别接口不受影响。

回滚优先恢复上一版 JAR、用户网页、管理端目录和 Nginx 配置，然后重启并验证。新增数据库列和表默认保留，以避免破坏上线后产生的数据；若必须恢复数据库，须同时恢复同一备份时点的管理音频目录。不得只恢复数据库或只删除上传目录。
